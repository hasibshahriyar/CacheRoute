# Glossary

## In Plain Words

Backend systems engineering uses several specialized terms. This glossary explains every technical term used across the CacheRoute docs in plain English.

---

- **Gateway:** A single front door server that sits between client apps and external services (here, AI model providers), handling auth, caching, rate limits, and routing in one place.
- **Proxy:** A server that forwards a client's request onward to another server and returns the response back to the client.
- **SSE (Server-Sent Events) / Streaming:** A way for a server to push words/tokens to the client gradually as the AI generates them (`text/event-stream`) instead of making the user wait for the entire answer to finish.
- **TTFT (Time to First Token):** How many milliseconds pass between sending a request and receiving the very first word of the AI's reply.
- **p50 / p95 / p99 Latency:** Latency percentiles. `p50` (median) means 50% of requests finished faster than this time; `p95` means 95% finished faster (only the slowest 5% took longer); `p99` measures the slowest 1% tail.
- **Semantic Cache:** A cache that recognizes two differently worded questions that mean the same thing (e.g., *"What is Redis?"* vs *"Explain Redis briefly"*) and reuses the saved answer.
- **Embedding:** A list of numbers (in CacheRoute, `384` numbers) generated by an AI model that captures the meaning of a sentence so similar meanings sit close together mathematically.
- **Cosine Similarity:** A score from `-1` to `1` measuring how closely two embedding vectors point in the same direction (`1.0` = identical meaning).
- **Similarity Threshold:** The minimum cosine similarity score (default `0.92` in CacheRoute) required before a semantic cache match is accepted as safe to reuse.
- **Circuit Breaker:** A safety switch that stops sending traffic to a broken or overloaded provider (`OPEN` state) for a cooldown period (`30s`–`5m`) before testing one single recovery request (`HALF_OPEN`).
- **Failover:** Automatically switching a failed request to a backup provider (e.g., Groq fails → switch to Gemini) so the user still gets a `200 OK` answer.
- **Token Bucket:** A rate-limiting algorithm where a bucket holds tokens up to a burst size (`20`) and refills at a steady rate (`1` token/sec = `60` RPM). Each request spends 1 token; empty bucket → `429 Too Many Requests`.
- **Observability:** Recording how fast every request ran, whether the cache hit, and which provider answered or errored, then turning those logs into charts and summary stats.
- **Prometheus:** A monitoring system that collects numeric metrics (counters and latency histograms) from an app's `/metrics` endpoint.
- **Grafana:** A visualization dashboard tool that reads metrics from Prometheus and draws live graphs of hit rate, errors, and p95 latency.
- **k6:** An open-source load-testing tool that simulates dozens or hundreds of concurrent users hitting an API to measure real speed and failure behavior.
- **Serverless / Fluid Compute:** Cloud hosting where you don't manage a virtual machine; Vercel spins up your code on demand and reuses warm instances across concurrent requests (Fluid Compute).
- **Cold Start:** The extra delay on the very first request after a serverless function or database (like Neon) has been asleep/idle.
- **Idempotency:** Guaranteeing that repeating an identical request or operation produces the exact same safe result without duplicating side effects.
- **Fail-Open vs. Fail-Closed:** When a helper database breaks: **fail-open** lets requests proceed anyway (used for Redis rate limiting so a Redis outage doesn't take down your API), while **fail-closed** blocks the request safely (used for API key auth when Postgres is unreachable so unverified callers cannot get in).
